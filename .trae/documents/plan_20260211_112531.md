# Comprehensive Project Analysis & Optimization Plan

## 1. Analysis & Issues Identified
*   **Architecture**: Currently follows a simple Presentation-only structure. To meet "Clean Architecture" standards, we need to decouple data logic.
*   **Code Quality**:
    *   `lib/components/embedded_counter.dart`: Potential API mismatch in `Styles` usage (similar to `theme.dart` fix).
    *   `lib/pages/contact.dart`: Missing form validation and state management.
    *   `pubspec.yaml`: `jaspr` version can be upgraded to `0.22.2` for better stability.
*   **Testing**: Test coverage is minimal (only one test file). Missing unit tests for business logic.
*   **Performance/Security**: Static assets are unoptimized. No input sanitization on the contact form (though client-side only for now).

## 2. Implementation Plan

### Phase 1: Architecture & State Management (Robust Solutions)
*   **Create Domain Layer**:
    *   `lib/domain/models/project.dart`: Entity for portfolio projects.
    *   `lib/domain/models/contact_form.dart`: Entity for form data.
    *   `lib/domain/repositories/project_repository.dart`: Interface definition.
*   **Create Infrastructure Layer**:
    *   `lib/infrastructure/repositories/project_repository_impl.dart`: Mock implementation (simulating API).
*   **Setup State Management (Riverpod)**:
    *   `lib/providers/project_provider.dart`: To fetch and filter projects.
    *   `lib/providers/contact_provider.dart`: To handle form state and submission.

### Phase 2: Refactoring & Fixes
*   **Refactor Pages**: Update `Projects` and `Contact` pages to consume the new providers instead of hardcoded data.
*   **Fix `EmbeddedCounter`**: Ensure `Styles` usage is consistent with the latest Jaspr API.
*   **Dependency Update**: Bump `jaspr` to `^0.22.2`.

### Phase 3: Comprehensive Testing (Test Coverage)
*   **Unit Tests**:
    *   Test `ProjectRepository` logic.
    *   Test `ContactProvider` state transitions (validation, submission).
*   **Component Tests**:
    *   Test `Contact` form interactions (entering text, clicking submit).
    *   Test `Projects` grid rendering.
*   **Configuration**: Add `coverage` settings to `analysis_options.yaml` (if applicable) or a test runner script.

### Phase 4: CI/CD Update
*   **Update Workflow**: Ensure `deploy.yml` runs `dart test` before building.

## 3. Deliverables
*   Refactored Codebase with Clean Architecture.
*   New Test Suite (`test/unit/`, `test/components/`).
*   Updated `pubspec.yaml` and `analysis_options.yaml`.
*   Final Report on changes.
